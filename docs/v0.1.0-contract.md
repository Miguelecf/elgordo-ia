# ElGordo IA v0.1.0 Contract

ElGordo is an OpenCode-first workflow where AI accelerates engineering without replacing human judgment. OpenCode owns semantic conversation; the Go CLI owns deterministic state and gates.

## Core Flow

1. Planner investigates and drafts an executable plan.
2. The engineer reviews and seals the exact plan bytes.
3. Executor implements only the sealed plan.
4. The engineer accepts, fixes, or replans.
5. QA independently compares plan and implementation, runs checks, and produces an exploratory charter.
6. The engineer grants final approval.

## Authority

| Concern | Authority |
|---|---|
| Requirements and architecture | Engineer through OpenCode |
| Workflow phase | `elgordo` CLI state |
| Approved scope | SHA-256 of the active plan revision |
| Cross-session continuity | Engram summaries and observations |
| Full working artifacts | Local `.elgordo/`, excluded from Git |
| Available skill index | Derived `.atl/skill-registry.md`, excluded from Git |
| Model choice | Engineer through OpenCode `/models` |

The CLI cannot prove human identity. In v0.1.0, a direct terminal command or an OpenCode permission prompt is the human-presence boundary.

## Work Units

1. Project state, plan revisions, transitions, and tamper detection.
2. CLI commands for lifecycle and human gates.
3. Global OpenCode assets for `/eg`, Planner, Executor, and QA.
4. Safe installer, Engram setup, Context7 registration, and diagnostics.
5. Curl bootstrap, release packaging, and isolated acceptance tests.

## Out of Scope

- Native Windows support.
- Runtimes other than OpenCode.
- Parallel active changes in one Git working tree. Linked worktrees have independent local state.
- Automatic model routing.
- CI enforcement or cryptographic human identity.
