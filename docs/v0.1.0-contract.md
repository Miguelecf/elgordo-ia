# ElGordo IA v0.1.0 Contract

ElGordo is an OpenCode-first workflow where AI accelerates engineering without replacing human judgment. OpenCode owns semantic conversation. ElGordo is the sole orchestrator and deterministic gate authority. The official OpenSpec CLI is the versioned artifact engine, not a competing workflow authority.

## Core Flow

```text
Human -> /eg conductor -> questioner -> planner -> [human plan approval]
                                      -> executor -> [human code approval]
                                      -> QA -> [human final approval]
```

The conductor may run bounded short iterations within one phase, but never crosses a review phase. The questioner only asks questions. Planner, executor, and QA return blockers to the conductor; the conductor and human own phase transitions and review gates.

## Authority

| Concern | Authority |
|---|---|
| Requirements, architecture, and approvals | Human |
| Workflow routing and gates | `elgordo` CLI and `eg` conductor |
| Versioned change artifacts | Official OpenSpec CLI under committed `openspec/` |
| Approved scope | Deterministic manifest of the plan and all Markdown OpenSpec artifacts |
| Cross-session continuity | Engram summaries and observations |
| Operational working state | Local `.elgordo/`, excluded from Git |
| Available skill index | Derived `.atl/skill-registry.md`, excluded from Git |
| Model choice | Engineer through OpenCode `/models` |

Architecture evidence resolves in this order: human, repository docs and `AGENTS.md`, ADRs, code, Engram, generic skills. The CLI cannot prove human identity. In v0.1.0, a direct terminal command or an OpenCode permission prompt is the human-presence boundary.

## Setup And Artifacts

`elgordo init` runs `openspec init --tools none`, preventing generated `/opsx-*` commands and OpenSpec agents. `/eg` is the sole human entrypoint.

OpenSpec artifacts live in `openspec/changes/<slug>/` as `proposal.md`, `specs/`, `design.md`, and `tasks.md`, and are committed. `.elgordo/`, `.engram/`, and `.atl/` are local state excluded through `.git/info/exclude`.

The installer requires OpenCode and Node.js 20.19.0 or newer. It does not install Node. It may offer Engram and, with consent, install only `@fission-ai/openspec@1.5.0` through npm. `--accept-openspec-install` supplies that consent non-interactively; doctor checks Node and OpenSpec.

Post-seal changes to the plan or any Markdown OpenSpec artifact require replan.

## Agent And Skill Resolution

The managed graph is declared in `internal/installer/assets/opencode/`:

| Contract | Location |
|---|---|
| `/eg` entrypoint | `commands/eg.md` |
| Agent-to-agent delegation | `agents/*.md`, `permission.task` |
| Agent-to-skill permission | `agents/*.md`, `permission.skill` |
| Runtime skill instructions | `skills/<name>/SKILL.md` |
| Dynamic external skill selection | `.atl/skill-registry.md` |

The conductor selects a phase agent and passes exact skill paths. Tests fail if a declared task or skill target does not exist, or if an embedded skill has no agent consumer. OpenCode permission frontmatter is the runtime boundary; Markdown prose explains behavior but does not grant capabilities.

## Quality Policy

- Strict TDD applies to behavior changes unless an explicit exception is recorded.
- Branches use `feat|fix|refactor|docs|test|chore/<slug>`.
- One Conventional Commit represents one complete work unit with code, tests, and docs together.
- A pull request over 400 LOC is a warning to propose a split, never a universal blocking rule.
- A human approves push and pull request creation.

OpenSpec scenarios use Given/When/Then Markdown. `eg-gherkin-verification` records an executed test or explicit manual evidence for each scenario. Executable `.feature` files are used only where the repository already has a BDD runner or the human explicitly chooses one.

## Work Units

1. Project state, plan revisions, transitions, plan-seal manifest, and tamper detection.
2. CLI commands for lifecycle and human gates.
3. Global OpenCode assets for `/eg`, questioner, planner, executor, and QA.
4. Safe installer, dependency checks, Engram setup, Context7 registration, and diagnostics.
5. Curl bootstrap, release packaging, and isolated acceptance tests.

## Out of Scope

- Native Windows support.
- Runtimes other than OpenCode.
- Parallel active changes in one Git working tree. Linked worktrees have independent local state.
- Automatic model routing.
- CI enforcement or cryptographic human identity.
